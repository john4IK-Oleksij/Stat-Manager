# SPEC 09.2 — Перевірка обмежень і крайових випадків

## Мета
Перевірити валідацію, SQL-безпеку та обмеження схеми.

## Перевірити
- Порожні/надто довгі `name` і `title`.
- Нульову, від'ємну та надмірну суму.
- Невідомі поля в JSON.
- Порожній `PATCH`.
- `null` у переданих полях оновлення.
- Невідомі ID та неіснуючі категорії.
- Дублікат назви категорії.
- Видалення категорії, на яку посилаються витрати.
- Символи `%`, `_`, `!` у пошуковому рядку.
- Неприпустимі значення `sort_by` та `order`.

## Робота асистента
- Підготувати матрицю тестів і очікуваних статус-кодів на основі PDF.
- Допомогти виправити виявлені дефекти, не змінюючи вимоги мовчки.

## Потрібна дія користувача
- Виконати перевірки локально й передати фактичні результати.

## Критерій завершення
Крайові випадки обробляються очікувано, SQL не формується з неконтрольованих фрагментів користувача.
