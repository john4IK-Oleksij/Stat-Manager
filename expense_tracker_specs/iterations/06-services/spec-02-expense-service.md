# SPEC 06.2 — Сервіс витрат

## Мета
Реалізувати бізнес-сценарії витрат.

## Вимоги
- Виклики `expense_repository`.
- Перевірка існування категорії під час створення або зміни категорії витрати.
- `commit` після успішної зміни.
- Для часткового оновлення передавати лише задані поля через `exclude_unset=True`.

## Робота асистента
- Створити `app/services/expense_service.py`.
- Не переносити HTTP-параметри безпосередньо в SQL.

## Потрібна дія користувача
- Перевірити створення, зміну категорії, оновлення та видалення через API.

## Критерій завершення
Сценарії витрат коректні, а посилання на неіснуючу категорію обробляється очікувано.
