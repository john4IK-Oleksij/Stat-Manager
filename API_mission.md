# Mission --- Expense Tracker API

## 1. Мета проєкту

Створити захищений REST API для обліку витрат на Python із FastAPI та
MySQL. Користувач має змогу створювати й переглядати категорії та
витрати, редагувати й видаляти витрати, фільтрувати та сортувати записи,
а також отримувати загальну статистику, статистику за категоріями й
місяцями.

**Критерій завершення:** усі маршрути з постановки задачі реалізовані та
перевірені; Swagger UI доступний за `/docs`; SQL-скрипти адміністратора
створюють базу, таблиці, користувача застосунку й тестові дані;
перевірено обмежені права `expense_app` та захист від SQL-ін'єкцій.

## 2. Незмінні технології

-   [ ] Python 3.12+
-   [ ] `uv`
-   [ ] FastAPI
-   [ ] Pydantic
-   [ ] `pydantic-settings`
-   [ ] `mysql-connector-python`
-   [ ] MySQL у XAMPP
-   [ ] Структура застосунку: `app/routers`, `app/services`,
    `app/repositories`, `app/config.py`, `app/database.py`,
    `app/schemas.py`, `main.py`
-   [ ] SQL-скрипти адміністратора зберігаються в каталозі `sql`

Не переходити на інші мови, фреймворки чи ORM без окремої зміни вимог.
Будь-яка зміна стека спочатку погоджується, а не впроваджується
самостійно.

## 3. Предметна модель

### Категорії (`categories`)

-   [ ] `id` --- додатне ціле число, генерується базою автоматично.
-   [ ] `name` --- непорожній рядок до 50 символів, унікальний.
-   [ ] Пробіли на початку й наприкінці назви прибираються.
-   [ ] Категорію з прив'язаними витратами видалити не можна: API
    повертає `409`, дані залишаються.
-   [ ] Категорії без витрат дозволені.

### Витрати (`expenses`)

-   [ ] `id` --- додатне ціле число, генерується базою автоматично.
-   [ ] `title` --- непорожній рядок до 100 символів.
-   [ ] `amount` --- `DECIMAL`, більше `0`, не більше `1 000 000 000`,
    максимум два знаки після коми.
-   [ ] `spent_on` --- коректна календарна дата.
-   [ ] `category_id` --- посилання на наявну категорію.
-   [ ] Кожна витрата належить рівно одній категорії.
-   [ ] Пробіли на початку й наприкінці назви витрати прибираються.

### Статистичні моделі

-   [ ] `Summary`: `expenses_count`, `total_amount`, `avg_amount`,
    `min_amount`, `max_amount`.
-   [ ] `CategoryStat`: `name`, `expenses_count`, `total_amount`,
    `avg_amount`.
-   [ ] `MonthStat`: місяць у форматі `YYYY-MM`, `expenses_count`,
    `total_amount`.
-   [ ] У статистиці за категоріями присутні також категорії без витрат
    із кількістю `0`.

## 4. Обов'язкові маршрути API

### Категорії

-   [ ] `POST /categories/` --- створити категорію; успіх `201`, дубль
    назви `409`.
-   [ ] `GET /categories/` --- отримати всі категорії.
-   [ ] `GET /categories/{id}` --- отримати одну категорію; відсутня
    `404`.
-   [ ] `PATCH /categories/{id}` --- перейменувати категорію; відсутня
    `404`, зайнята назва `409`.
-   [ ] `DELETE /categories/{id}` --- видалити категорію; успіх `204`,
    відсутня `404`, є витрати `409`.

### Витрати

-   [ ] `POST /expenses/` --- створити витрату; успіх `201`, відсутня
    категорія `404`.
-   [ ] `GET /expenses/` --- список із підтримкою параметрів:
    -   [ ] `q` --- пошук за частиною назви, довжина 1--50 символів.
    -   [ ] `category_id` --- фільтр за категорією.
    -   [ ] `sort_by` --- лише `spent_on`, `amount` або `title`; типово
        `spent_on`.
    -   [ ] `order` --- лише `asc` або `desc`; типово `asc`.
    -   [ ] `limit` --- 1--100; типово `20`.
    -   [ ] `offset` --- не менше `0`; типово `0`.
-   [ ] `GET /expenses/{id}` --- отримати одну витрату; відсутня `404`.
-   [ ] `PATCH /expenses/{id}` --- частково змінити дозволені поля
    `title`, `amount`, `spent_on`, `category_id`; відсутня витрата
    `404`.
-   [ ] `DELETE /expenses/{id}` --- видалити витрату; успіх `204`,
    відсутня `404`.

### Статистика

-   [ ] `GET /stats/summary` --- кількість, сума, середнє, мінімум і
    максимум витрат.
-   [ ] `GET /stats/by-category` --- статистика для кожної категорії,
    включно з порожніми; підтримка `min_count`.
-   [ ] `GET /stats/by-month` --- кількість і сума витрат за місяцями у
    форматі `YYYY-MM`.

## 5. Валідація та контракти

-   [ ] Ідентифікатори --- додатні цілі числа.
-   [ ] Назви не можуть бути порожніми; зовнішні пробіли обрізаються.
-   [ ] Сума більша за нуль, не перевищує мільярд і має не більше двох
    знаків після коми.
-   [ ] Некоректні календарні дати відхиляються.
-   [ ] Зайві поля у запитах відхиляються з `422`.
-   [ ] У `PATCH` дозволено змінювати лише визначені поля; спроба
    змінити `id` чи інше заборонене поле відхиляється з `422`.
-   [ ] Поведінка HTTP-статусів відповідає вимогам для кожного маршруту.

## 6. База даних і безпека

-   [ ] Адміністратор створює базу, таблиці, користувача БД і тестові
    дані через SQL-скрипти; застосунок цього не робить.
-   [ ] Застосунок підключається до БД лише користувачем `expense_app`.
-   [ ] `expense_app` має лише необхідні права `SELECT`, `INSERT`,
    `UPDATE`, `DELETE` на дані.
-   [ ] `expense_app` не може виконувати `CREATE TABLE`, `ALTER TABLE`,
    `DROP TABLE` або читати системні таблиці MySQL.
-   [ ] Права на стовпці не дозволяють змінювати `id`.
-   [ ] Для з'єднань використовується пул; якщо вільних з'єднань немає,
    API повертає `503`.
-   [ ] Параметри підключення читаються зі змінних середовища та `.env`
    через `pydantic-settings`.
-   [ ] Пароль не записується в коді та має щонайменше 12 символів.
-   [ ] Усі SQL-операції параметризовані: `SELECT`, `INSERT`, `UPDATE`,
    `DELETE`.
-   [ ] Для полів `UPDATE` застосовується білий список дозволених назв.
-   [ ] Для `sort_by` і `order` застосовується білий список дозволених
    значень.
-   [ ] Символи `%` і `_` у пошуку `q` шукаються буквально, а не
    трактуються як шаблони.
-   [ ] У БД є `UNIQUE` для назви категорії, `CHECK (amount > 0)` та
    зовнішній ключ, який забороняє видалення категорії з витратами.
-   [ ] Клієнт не отримує текст SQL, назви таблиць або внутрішні деталі
    помилок БД.
