# 📊 Expense Tracker (Stat Manager)

Сучасний, швидкий та адаптивний веб-застосунок для обліку особистих фінансів, керування категоріями витрат та перегляду наочної аналітики у вигляді SVG-графіків.

Побудований за клієнт-серверною архітектурою: надійний **Python / FastAPI backend** з базою даних **MySQL** та легкий, високопродуктивний **Vanilla JS / HTML5 / CSS3 frontend** без сторонніх бібліотек та важких фреймворків.

---

## 🌟 Основні можливості

### 1. Головна панель («Огляд витрат»)
- **4 ключові показники (KPI):** Загальна сума витрат, загальна кількість чеків, середній чек, діапазон мінімальної та максимальної витрат.
- **Кільцева діаграма часток категорій (SVG Donut Chart):**
  - Розрахунок відсотків та відображення загальної суми в центрі.
  - **Інтерактивність:** наведення підсвічує сектор, а **клік на сектор або легенду** автоматично перенаправляє на сторінку «Витрати», відфільтровану за обраною категорією.
  - Динамічна генерація кольорів (на основі золотого кута $137.5^\circ$), що забезпечує унікальний відтінок для будь-якої кількості категорій.
- **Стовпчиковий графік динаміки (SVG Bar Chart):**
  - Помісячний розподіл витрат із масштабованими стовпчиками та підказками сум (tooltips).
- **Останні витрати:** список 5 найсвіжіших операцій із швидким переходом до повного списку.
- **Швидка дія:** кнопка «+ Додати витрату» у верхній частині екрана.

### 2. Керування витратами («Усі витрати»)
- **Таблиця витрат:** дата (`DD.MM.YYYY`), назва, кольоровий бейдж категорії, сума з вирівнюванням по правому краю, кнопки редагування та видалення.
- **Серверна фільтрація та пошук:**
  - Живий пошук за назвою (`q`) із затримкою debounce (350 мс);
  - Фільтр за категорією;
  - Сортування за датою (`spent_on`), сумою (`amount`) або назвою (`title`);
  - Порядок сортування: спадаючий ($\downarrow$) або зростаючий ($\uparrow$);
  - Кнопка швидкого скидання всіх фільтрів.
- **Пагінація:** порційне завантаження (по 20 записів) з кнопками «Попередня» / «Наступна» та лічильником сторінок.
- **Модальне вікно (Створення та Редагування):**
  - Повна валідація на клієнті та сервері (сума $> 0$, максимум 2 знаки після коми, валідна дата, обов'язковий вибір категорії).

### 3. Керування категоріями («Категорії»)
- **Створення категорій:** швидка форма додавання з перевіркою унікальності назви.
- **Адаптивна grid-сітка:** картки категорій з підрахунком кількості витрат.
- **Перейменування:** модальне вікно з миттєвим збереженням через `PATCH /categories/{id}`.
- **Розумний захист від видалення (RESTRICT):**
  - Якщо до категорії прив'язані записи витрат, система блокує видалення і повідомляє причину (*«Категорія містить X витрат...»*).
  - Видалення дозволено лише для порожніх категорій після обов'язкового підтвердження в модальному вікні.

### 4. Повна статистика («Статистика»)
- **Блок 1:** Загальні підсумкові показники.
- **Блок 2:** Аналітика за категоріями (інтерактивна кільцева діаграма + таблиця із загальною та середньою сумою для кожної категорії).
- **Блок 3:** Помісячний звіт (стовпчиковий графік + таблиця помісячних витрат).

## 🧭 Сервісні інструменти та UI-фічі

### Sticky-індикатор стану API (Health Check)
У правому нижньому кутку кожної сторінки закріплено віджет перевірки з'єднання з сервером:
- **Зелена крапка (`API Online`):** бекенд активний, відображається час відгуку сервера (пінг у мс).
- **Червона крапка (`API Offline`):** сервер вимкнений або недоступний.
- **Автоматичне опитування:** кожні 20 секунд у фоновому режимі виконується перевірка ендпоінта `GET /health`.
- **Ручна перевірка:** клік на віджет у будь-який момент ініціює миттєвий повторний пінг.

### Документація Swagger у футері
У підвалі кожної сторінки розміщено пряме посилання **`Swagger (API Docs) ↗`**, яке веде на інтерактивну OpenAPI-документацію бекенду (`http://127.0.0.1:8000/docs`).

### Мобільна адаптивність
- Повна підтримка пристроїв від 320px до 4K.
- Адаптивний Header із логотипом.
- Бургер-меню для мобільних екранів зі шторкою, затемненням фону та закриттям по `Esc`.

## 🚀 Інструкція із запуску

### 1. Налаштування бази даних та оточення бекенду
Переконайтеся, що у вас встановлено Python 3.11+ та запущено сервер MySQL.
У корені проєкту перевірте наявність файлу `.env`:
```env
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_DATABASE=expense_tracker
MYSQL_USER=expense_app
MYSQL_PASSWORD="your_password"
```

### 2. Запуск бекенду (FastAPI)
Відкрийте термінал у кореневій папці проєкту (`D:\KURS PYTHON-DJANGO\DZ -15\Stat Manager`):

**У PowerShell:**
```powershell
# Активація віртуального оточення
.\.venv\Scripts\activate

# Запуск Uvicorn-сервера
uvicorn app.main:app --reload
```

**У Git Bash:**
```bash
source .venv/Scripts/activate
uvicorn app.main:app --reload
```
Після успішного запуску бекенд буде доступний за адресою: [http://127.0.0.1:8000](http://127.0.0.1:8000).

---

### 3. Запуск фронтенду
Фронтенд є повністю статичним (HTML/CSS/JS) і не потребує складання (npm build):

1. **Спосіб 1 (Рекомендований — Live Server):**
   - Відкрийте папку проєкту у VS Code або Antigravity.
   - Клацніть правою кнопкою миші на `frontend/index.html` і виберіть **Open with Live Server**.
2. **Спосіб 2 (Звичайний запуск у браузері):**
   - Перейдіть у папку `frontend/` та відкрийте файл `index.html` подвійним кліком.
3. **Спосіб 3 (Локальний HTTP-сервер Python):**
   ```bash
   python -m http.server 5500 --directory frontend
   ```
   Відкрийте [http://localhost:5500](http://localhost:5500) у вашому браузері.
